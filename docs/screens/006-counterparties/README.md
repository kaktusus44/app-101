# Контрагенты и приглашения

## Сценарий

1. Организация открывает список контрагентов.
2. Выбирает категорию: заказчик, партнёр, подрядчик, поставщик или сотрудник.
3. Указывает имя и логин; временный пароль генерируется автоматически.
4. Система создаёт приглашение с непрозрачным токеном в URL.
5. Приглашённый открывает ссылку и входит с ролью клиента, доступной только для просмотра.

Пароль не включается в URL. Организация копирует ссылку, логин и временный пароль
одним подготовленным сообщением.

## Ограничение прототипа

Приглашения сейчас хранятся в `localStorage`, поэтому ссылка работает только в той же
demo-сессии браузера. Для рабочего приглашения на другом устройстве токен, хеш пароля,
срок действия и статус использования должны храниться на backend.

## Backend-контракт

- создание приглашения доступно только организации;
- токен одноразовый и имеет срок действия;
- пароль хранится только в виде хеша;
- после принятия создаётся пользователь с ролью `client`;
- повторное использование и отозванное приглашение возвращают ошибку.
